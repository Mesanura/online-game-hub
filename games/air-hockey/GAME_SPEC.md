# 气垫球

`air-hockey@1.1.0` 是双人、60 Hz、服务器权威的气垫球。平台管理房间、稳定席位、准备、重连、投降确认、多轮和留档；游戏管理几何、操作、碰撞与比分。

## Setup、席位与胜负

Setup 的严格 `{ type: "SET_TARGET_SCORE", targetScore: 5 | 7 | 11 }` 仅房主可提交，默认 7 分。同值拒绝为 `SETUP_UNCHANGED`，非房主拒绝为 `NOT_OWNER`；接受不同设置清空准备。两人分别准备后才能开始。

finalize 固定 `playerOrder = [owner, other]`，不依赖 slots 数组顺序、不消费 Setup RNG。P1 为房主、蓝色，P2 为橙色；首局和重新对局均保持此对应，下一局保留目标分数。P1 的权威半场位于下方，P2 位于上方。P2 的画面仅沿水平中线反射，左右不翻转。

球整体越过顶端球门线时 P1 得分，整体越过底端球门线时 P2 得分；越线时球心须在两柱之间，球门柱接触先于进球。门柱扫掠负责阻挡，整球越线后不再要求球的水平投影也完全位于门洞内，避免斜擦门柱漏计分后飞出场外。每球一分，达到目标即胜，无领先两分或加时。`RESIGN` 在活跃时刻有效，双方同 tick 投降按 playerOrder 先出现者生效，比分保留实际值。Outcome 为 `WIN`，reason 为 `SCORE | RESIGNATION`，包含 winnerSlotId、最终 scores，投降额外包含 resignedSlotId。

## 几何与操控

逻辑场地 600×1020，每像素 1000 个整数单位。球半径 18、球拍半径 42、中圈半径 132；上下球门开口均为 x=216..384。P1/P2 球拍初始位置分别为 (300,765)/(300,255)，球初始位置为 (300,510)。边框视觉圆角半径为 18，球心可达边界与直角偏移边界一致。

输入是严格 `{ type: "CONTROL", target: { x, y } | null }` 或 `{ type: "RESIGN" }`。指针 x/y 均为 0..10000 的整数，以玩家自己的完整球场视角归一化；这只是想移动到的目标，不是实体坐标。Core 由服务器确定的 actor 映射 P2 的 y，夹紧球拍整个圆形到己方半场和场内，再朝目标移动。球拍最大速度 30000 单位/tick（30 像素/tick），斜向按欧氏距离限制。null 立即停止；新输入重置 inputAge，随后每 tick 加一，到 45 时清除目标。未过期时沿用目标。输入采用 latest，同 tick 仅最后一条交给模拟；Surface 在投降期间停止移动输入。

鼠标跟随和单指拖动的表现、停止事件、插值、音效与布局由独立 Surface 负责。客户端不提交速度、actor、tick、命中、分数或 Outcome。

## 发球与物理

阶段为 `SERVE → RALLY → FINISHED`，每次非终局得分回到 `SERVE`：双方归位、清空目标和速度，球静止于中央，rally 加一。首球由 P1 发球，此后由失分方发球。等待无时限。只有发球方球拍朝球形成相对法线速度为负的有效接触，才能启动 RALLY；另一方不移动待发球、不产生碰撞事件。启动 tick 的余下时间仍只处理发球方，下一 tick 才处理双方。

球拍按服务器本 tick 的实际移动产生运动轨迹，与球进行相对运动扫掠。有限边框由左右直线、上下四段直线及四个球门柱端点组成；球门柱使用球半径扩张后的圆检测。按最早接触时间迭代，时间误差阈值为 1e-8；同刻按边框/门柱、P1、P2、进球排序，边界内部依次为左、右、上、下、左上门柱、右上门柱、左下门柱、右下门柱。

碰撞法线 n 从障碍物指向球，球与球拍的相对速度为 u；仅当 `u·n < 0` 时将球速度减去 `2(u·n)n`。边框速度为零。球没有自然阻力，直线边框只反转法线速度；移动球拍传递的动量决定击球速度，总速率上限 28000 单位/tick。若限速后球拍仍沿法线追入球内，则沿原目标方向按比例削减本 tick 剩余运动，使球拍的法线速度不超过球的法线速度；不改变球拍方向，避免贴边斜碰越过边框或中线。分离中的接触只消除重叠，不重复注入能量。接触后分离 2 个整数单位。

每 tick 最多解析 16 次常规接触；耗尽时将球夹紧到实体边框内，保留本 tick 最大球速（脱困最低 6000、最高 28000 单位/tick），寻找可扫掠通过的水平或竖直出口。挤压球拍沿出口的垂线退让，整个 tick 的球拍位移仍受速度上限、半场和场地边界约束。优先选择球拍退让平方距离之和最小的出口；相同时按朝中场 y、朝中场 x、反向 y、反向 x 排序，中线相等时取负方向。出口必须通过既有边框、门柱、球拍和进球线扫掠检查；成功后球继续走完剩余时间，无法腾出合法出口则保留球速并分离重叠，下个 tick 继续解析。脱困不瞬移球到其他区域、不直接判分、不消费 RNG。

中间扫掠求根使用固定顺序的 JavaScript number，tick 末位置 Math.round、速度 Math.trunc，负零归一为零；下一 tick 仅从整数状态重建。Core 不使用环境时间、I/O 或全局随机，Gameplay RNG 保持不变。

## 历史版本

`1.0.0` 的 Core、schema、manifest 和常量独立冻结，继续验证原有计分与投降 golden。其球拍上限为 20000 单位/tick；碰撞次数耗尽会停止球速及剩余运动，保留原有墙边、角落夹停行为；进球还要求越线时球的水平投影完全位于门洞内。`1.1.0` 提高球拍上限，修复挤压、高速追球和斜擦门柱漏计分，不能用于重建旧版记录。两版使用相同的 Config、Input、View、Outcome、Setup 和记录格式，独立 Surface 明确支持两版。

## 投影、事件与记录

公开 View 包含场地、players 的席位/颜色、yourSide、球和球拍位置、目标分数/比分、tick、rally、phase、server、Outcome 与事件；不包含权威速度、指针目标、输入租期、seed 或 canonical journal。

碰撞事件为 PADDLE/WALL/GOAL，包含单调 id、发生 tick、权威接触位置、0..1000 强度及相关 side/edge。最多保留最近 60 tick 的 64 条；事件从 canonical 输入确定性生成，不单独作为输入记录。双方声音与边框流光由相同事件驱动，镜像仅属于渲染。

使用平台 V6、Realtime Protocol V1、Bridge V2、Realtime Replay Format V1。能力为 record-only：服务器记录并精确验证，账户可查看比分，不提供玩家播放。历史投影依据 replay header 原始玩家顺序显示我方/对方比分，不根据分数猜测投降胜者。

验证遵循 [测试策略](../../docs/TESTING.md)，规则、输入解释、量化或碰撞次序改变时评估新的 gameVersion；纯表现改动独立提升 surfaceVersion。
