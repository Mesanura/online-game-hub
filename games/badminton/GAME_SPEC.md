# 火柴人羽毛球

当前 `badminton@1.2.0` 是原创火柴人画面的双人联机街机羽毛球。Platform 负责身份、私人房间、逐人准备、重连、多轮、关闭和留档；游戏负责移动、球路、碰撞与比分。历史 `1.0.0` 和 `1.1.0` 的 Core、schema、常量与 golden records 独立冻结，保留旧发球、网高与命中规则。

## 场地与操作

固定 `60 Hz`，逻辑画面 `1000 × 600`，每像素对应 1000 个整数单位；地面 y=500，界线 x=80/920，球网 x=500、顶端 y=370（网高 130）。双方只能在自己的半场移动，球拍只能击打自己一侧的球；忽略人物身体碰撞，不允许同一方连续触球。

`1.2.0` 常规命中椭圆中心为朝网 40、脚底上方 85 像素，横纵半径为 100/105；另有低位捞球椭圆，中心为身后 20、脚底上方 35，半径为 105/65，覆盖后脚后下方。两个区域取并集，仍先判网、落地和界外，且必须处于有效挥拍窗口、己方半场并未连续触球。改变网高和命中范围会改变旧日志的轨迹与判分，因此新增规则版本。

输入为 strict `{ type: "CONTROL", move: -1 | 0 | 1, jump: boolean, serve: boolean, shot: "NONE" | "CLEAR" | "DROP" | "SMASH" }` 或 `{ type: "RESIGN" }`。A/D 或左右方向键移动，W/上方向键/空格起跳，S 仅发球，J 高远球、K 扣杀、L 吊球；触屏提供等价按钮。起跳与发球按下边沿触发一次，松开才能再次触发；挥拍可按住，10 tick 有效窗口、24 tick 冷却，触球不重启窗口。按住操作时 Surface 每 150 ms 刷新输入；45 tick 未刷新后 Core 归零控制，失焦/隐藏/释放立即发送归零 intent。快速发球点按在 Surface 保持请求至权威起手确认，防止同 tick 的释放覆盖；重连、新局、隐藏、失焦清除请求。

## 球路与判分

人物水平速度 5500、起跳速度 -11000、重力 500。羽毛球每 tick 横速乘 978/1000 后截断，竖速乘 985/1000 后截断再加 320，上限 18000。两个方向的初速度均通过同一整数积分二分求解，高远球/吊球/扣杀分别使用 86/68/26 tick，落点指向对面 x=830/620/770（右侧镜像）；横速明显递减、后段下降更陡。球拍不自动追球，必须跑到球附近并在窗口内挥拍。扣杀要求人物至少离地 45 像素且击球点高于网顶 30 像素，否则按高远球处理。

球低于角色脚底上方 80 像素的腰线时使用 `UNDERHAND`，否则为 `OVERHEAD`；阈值随跳跃平移，触球前更新、触球后锁定。低位 J 高远、L 吊球保持区别，K 降级高远球。Surface 左侧上手从头后上方向前上方顺时针挥，下手从后下方向前上方逆时针挑；右侧镜像，权威触球位置用于拍头对齐。

每 tick 先按固定 players 顺序应用输入并处理投降，再更新人物和挥拍，最后用四段扫掠移动球。每段按网、地面、外场边界、球拍顺序判定；高速球不能穿网。球触网由最后击球者失分，落在某半场界内由该侧失分，落在界线外或飞出整个画面由最后击球者失分；压边线算界内。比分由 Core 产生，浏览器不裁定碰撞。

首发方固定在左侧。得分后停留 90 tick 展示结果、双方回位，由得分方发球。`SERVE` 无限等待，没有自动发球和超时失分。发球方可持球移动、跳跃和空中发球；后场三分之二边界为 x=360/640，前脚前端偏移为朝网方向 20 像素，身体发球活动范围因此为左侧 x=80..340、右侧 x=660..920，空中相同。前进到上限后实际位移为零，前脚接地点在线上，不继续踏步。接球方沿用正常半场范围。

发球方新的 `serve: true` 边沿进入 `SERVING`，第 1 tick 起手、第 6 tick 击出高远球进入 `RALLY`，总动作 18 tick 后恢复上手准备姿势；起手期间仍运行移动、跳跃与重力，出球后恢复完整半场活动范围。持球点为朝网方向 40 像素、脚底上方 70 像素；球在出球前一直跟随该点。得分停留期间、非发球方和回合内的 S 不排队启动后续发球，跨球保留按键边沿状态以避免长按连发。游戏无局间换边。

默认目标 7 分，可选 11/21 分。至少达到目标且领先 2 分获胜；封顶分别为 11/15/30 分，封顶一分决胜。比赛为单局。任意活跃时刻可通过平台确认投降，产生 `RESIGNATION`；正常结束为 `SCORE`。同 tick 双方投降按 players 顺序先出现者生效。终局后 step 拒绝继续。

## Setup、投影与版本

V6 Setup 默认房主首发，房主可选自己/对方/随机首发与 7/11/21 分。接受不同设置清空双方准备，相同设置拒绝为 `SETUP_UNCHANGED`；非房主不能修改。随机首发只消耗 Setup RNG。下一局保留实际 LEFT/RIGHT 顺序和比分设置，不重抽随机；双方必须分别准备。

公开 View 包含场地（含两条发球线和前脚偏移）、人物坐标与实际移动状态、挥拍类型/开始 tick/剩余 tick、最近触球 tick/位置/有效球路、球坐标、比分、阶段、发球方、回合击球数、最长回合、上一分原因与 Outcome；不含速度、持续输入、输入租期、seed、原始 State 或 canonical journal。Gameplay 不消费 RNG，相同版本、Config、players 和输入日志逐 tick 得到完全一致的结果。

Surface 按 exact 规则版本解析 View/Input，旧自动发球版本不发送 `serve`；球网和接触动画必须与对应公开几何对齐。人物、球场投影、粒子、音效与布局说明集中在 [Surface README](../../game-surfaces/badminton/README.md)。

使用 Realtime Protocol V1、Realtime Replay Format V1 与 Bridge V2。全部支持版本为 `record-only`：服务器保存并验证比赛，账户可查看战绩，不提供玩家回放。只发布 Setup/Play Surface。改变旧日志结果的规则调整须评估新 gameVersion，影响产物的纯视觉修改提升 surfaceVersion。
