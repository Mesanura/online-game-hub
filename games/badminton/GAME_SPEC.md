# 火柴人羽毛球

`badminton@1.0.0` 是原创火柴人画面的双人联机街机羽毛球。Platform 负责身份、私人房间、逐人准备、重连、多轮、关闭和留档；游戏负责移动、球路、碰撞与比分。

## 场地与操作

固定 `60 Hz`，逻辑画面 `1000 × 600`，每像素对应 1000 个整数单位；地面 y=500，界线 x=80/920，球网 x=500、顶端 y=340。双方只能在自己的半场移动，球拍只能击打自己一侧的球；忽略人物身体碰撞，不允许同一方连续触球。

输入为 strict `{ type: "CONTROL", move: -1 | 0 | 1, jump: boolean, shot: "NONE" | "CLEAR" | "DROP" | "SMASH" }` 或 `{ type: "RESIGN" }`。A/D 或左右方向键移动，W/上方向键/空格起跳，J 高远球、K 扣杀、L 吊球；触屏提供等价按钮。起跳按下触发一次，松开才能再次起跳；挥拍可按住，10 tick 有效窗口、24 tick 冷却。按住操作时 Surface 每 150 ms 刷新输入；45 tick 未刷新后 Core 归零控制，失焦/隐藏/释放立即发送归零 intent。

## 球路与判分

人物水平速度 5500、起跳速度 -11000、重力 500。羽毛球每 tick 横速乘 992/1000 后截断，竖速加 320，上限 18000。高远球/吊球/扣杀分别由 Core 解出 86/68/26 tick 的整数轨迹，落点指向对面 x=830/620/770（右侧镜像）；球拍不自动追球，必须跑到球附近并在窗口内挥拍。扣杀要求人物至少离地 45 像素且击球点高于网顶 30 像素，否则按高远球处理。

每 tick 先按固定 players 顺序应用输入并处理投降，再更新人物和挥拍，最后用四段扫掠移动球。每段按网、地面、外场边界、球拍顺序判定；高速球不能穿网。球触网由最后击球者失分，落在某半场界内由该侧失分，落在界线外或飞出整个画面由最后击球者失分；压边线算界内。比分由 Core 产生，浏览器不裁定碰撞。

首发方固定在左侧。每球开始有 120 tick 自动发球倒计时；得分后停留 90 tick 展示结果、双方回位，由得分方发球。发球自动使用高远球，避免无人发球使比赛停滞。游戏无局间换边。

默认目标 7 分，可选 11/21 分。至少达到目标且领先 2 分获胜；封顶分别为 11/15/30 分，封顶一分决胜。比赛为单局。任意活跃时刻可通过平台确认投降，产生 `RESIGNATION`；正常结束为 `SCORE`。同 tick 双方投降按 players 顺序先出现者生效。终局后 step 拒绝继续。

## Setup、投影与版本

V6 Setup 默认房主首发，房主可选自己/对方/随机首发与 7/11/21 分。接受不同设置清空双方准备，相同设置拒绝为 `SETUP_UNCHANGED`；非房主不能修改。随机首发只消耗 Setup RNG。下一局保留实际 LEFT/RIGHT 顺序和比分设置，不重抽随机；双方必须分别准备。

公开 View 包含场地、人物坐标与挥拍表现、球坐标、比分、阶段、发球方、回合击球数、最长回合、上一分原因与 Outcome；不含速度、持续输入、输入租期、seed、原始 State 或 canonical journal。Gameplay 不消费 RNG，相同版本、Config、players 和输入日志逐 tick 得到完全一致的结果。

使用 Realtime Protocol V1、Realtime Replay Format V1 与 Bridge V2；不修改任何公共协议。首版为 `record-only`：服务器照常保存并验证比赛，账户历史可查看记录，但不提供玩家回放。只提供独立 Setup/Play Surface。任何改变旧日志结果的规则调整必须提升 gameVersion，纯视觉修改只提升 surfaceVersion。
