# M8 Shared Public API 审计

本审计记录 M8 编码前确认的现有边界及所需公共变更，并作为实现后的兼容性证据。旧回合制游戏继续使用 Protocol V5、Replay Format V1、`GameDefinition`、`GameClientModule`、`game.action`、`match.snapshot` 和 revision pipeline。

| 变更                           | 跨 package 价值                                                                                    | 兼容性与迁移                                                                                                                                                                  | Contract tests                                                                                                                       |
| ------------------------------ | -------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Catalog manifest runtime 判别  | Web、registry 与 Game Server 必须在不识别 `pong` id 的情况下选择 turn-based/realtime 组合          | 既有 manifest 的 `runtime: "turn-based"`、字段和值不变；Pong 使用独立 realtime manifest。旧 turn-based resolver 对 realtime id 返回 `undefined`，新增 exact realtime resolver | registry 校验 catalog 唯一性、default Config、exact/current 两类 resolver 与 lazy client loader                                      |
| Realtime Protocol V1           | server runtime 与 client host 需要共同验证最小 input、完整 snapshot、ack 与 rejection              | 新增独立常量/schema/message channel；不把 realtime envelope 加入 V5 `clientMessageSchema`/`serverMessageSchema`，不修改旧字段                                                 | protocol tests 覆盖伪造 actor/slot/tick/State/score/Outcome/client time、超大 input、版本、viewer 与独立解析                         |
| `realtime-game-sdk`            | Pong simulation、server runtime、registry 与 replay verifier共享 deterministic simulation contract | 新 package，不导入或扩展 `GameDefinition`；Realtime Replay Format V1 有独立 header/event/verifier                                                                             | SDK tests 覆盖 identifier/RNG、continuous tick rebuild、sequence/tick/actor/input/outcome tampering                                  |
| `realtime-game-server-runtime` | composition 需要无具体游戏依赖的 fixed-tick single writer、input queue、ack 与 replay port         | 新 package；不依赖 `game-server-runtime`。现有 room/action runtime 无修改                                                                                                     | runtime tests 覆盖 effective tick、stable slot ordering、input sequence/idempotency、终局、store conflict 与 scheduler serialization |
| `realtime-game-client-sdk`     | Web 与 Phaser client 需要无游戏/Phaser依赖的 transport host 与 visual interpolation contract       | 新 package；不依赖 `game-client-sdk`，V5 lifecycle 只作为平台消息复用                                                                                                         | host/interpolation tests 覆盖最小 input、ack、snapshot monotonicity、viewer fail-closed、rejection 与只影响显示的 interpolation      |
| Pong registry/package exports  | catalog、server composition、Web lazy loader需要显式发现 Pong                                      | 只增加静态登记和 `/manifest`、`/core`、`/client` exports；禁止目录扫描                                                                                                        | registry、Pong Core/client/golden tests                                                                                              |

数据库评估已落地：离散 `replay_actions(sequence, action JSONB)` 无法用列约束表达 realtime tick/runtime，因此 realtime 使用专用 `realtime_replays`、`realtime_replay_events`、`realtime_rooms`、`realtime_room_players`、`realtime_matches` 和 `realtime_match_players` 表及对应 adapter。Realtime replay 的 `tick`、runtime、format、seed、outcome 和完成状态均有显式列/约束，并由 exact verifier 在读取端再次校验。
